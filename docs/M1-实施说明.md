## 1. M1 目标与验收

M0 已把聊天原型重构为基础架构；M1 使其成为「本地优先任务助手」：

1. **任务收件箱与 CRUD**：查看、创建、编辑（含解除截止时间）、完成、取消任务；今日视图。
2. **模型配置持久化**：非敏感配置（名称/Base URL/模型/温度/最大输出/流式/能力标签）落 shared_preferences；API Key 进平台安全存储；启动时加载进内存缓存，`currentProfile`/`apiKey` 保持同步 getter。
3. **AI 计划预览与确认**：聊天页「拆解为任务」→ 结构化 JSON 校验 → `AIPlan`（awaitingConfirmation）落库 → 任务页待确认区展示预览卡 → 用户确认后一次性写入任务表（原子），拒绝则标记 rejected。
4. 全程不触网/不依赖真实 LLM/不依赖平台安全存储的测试（领域/数据/用例/widget 四层）。

验收标准（对应设计 §12 单机子集）：
- 可创建/编辑（含清空截止时间）/完成任务；今日视图含过期任务，过期项红色标注。
- AI 拆解结果在用户确认前**不会**修改任务表；非法 JSON 一律拒绝且不落任何业务数据。
- 每次确认写入后，`AIPlan` 与任务在同一事务内完成，状态 applied + confirmedAt/appliedAt，可追溯（模型、提示版本、来源消息、会话）。
- 保存设置不因「未重新输入 key」清空安全存储中的 key（回填守卫，B2）。
- `flutter analyze` 0 issues；`flutter test` 全绿（数量在前一里程碑基础上增加）。

## 2. 明确不做（防止蔓延）

- **不做项目（Project）UI**：`projectId` 字段保留，M1 恒 null；Projects 表与 UI 留 M2。
- **不做子任务 UI**：`parentTaskId` 保留，M1 恒 null。
- **不做日历**：AIPlanChange 的 `scheduleTask`/`calendarEntryId` M1 不产生、不处理（校验时见到即抛）。
- **不做同步**（M2）：任务/AI 计划写入不走 SyncOperation；在同一事务里预留插入点（注释标注）。
- **不做自动过期定时器**：`expired` 状态枚举保留；M1 只支持用户拒绝（rejected），自动过期策略留 M2。
- **不自动识别任务意图**：拆解仅由显式按钮触发。
- **不改 M0 视觉基线**：主题、配色、会话/聊天/设置页现有布局不动；新增任务区与导航遵循现有 Material 风格与蓝色系。
- **与设计基线的偏离**（用户已确认，防对照基线误判为漏做）：导航先做三区而不是五区（日历/健康 M2+ 再加）；首页不做「最近对话/今日重点」卡片（今日重点并入任务页今日视图）。

### 4.2 AIPlanRepository（新接口，domain/repositories/ai_plan_repository.dart）

```dart
/// AI 计划仓储。M1 实现；确认/拒绝与应用变更保持原子。
abstract interface class AIPlanRepository {
  /// 监听「待确认」（awaitingConfirmation）计划，按 createdAt 正序。
  Stream<List<AIPlan>> watchPending();

  /// 一次性获取待确认计划。
  Future<List<AIPlan>> getPending();

  /// 保存计划（草稿/待确认）。
  Future<AIPlan> save(AIPlan plan);

  /// 确认：把计划内变更应用到任务表并把计划置为 applied（同事务）。
  Future<void> confirm(String planId);

  /// 拒绝：标记 rejected + rejectedAt。
  Future<void> reject(String planId);
}
```

实现要点：
- **confirm 原子性（Drift 版）**：一个 `database.transaction` 内完成「读计划（必须 awaitingConfirmation，否则抛 `ConflictException`）→ 对每条 createTask 变更经 `taskFromPlanChange`（§4.5）物化为 `Task` → `TaskRepository.applyChanges` → 计划行置 applied + confirmedAt/appliedAt + version+1」。Drift 2.35.2 嵌套事务复用外层（已核实，SAVEPOINT），内层异常冒泡即回滚外层。**confirm 不得 catch/吞掉 applyChanges 抛出的异常**。
- **confirm 原子性（内存版）**：`MemoryTaskRepository.applyChanges` 采用「先全量校验（含目标存在性），再一次性提交」，天然全或无；`MemoryAIPlanRepository` 注入同一 `MemoryTaskRepository` 实例（DI 装配见 §7），先校验 plan 状态再调用 applyChanges。双实现统一跑 §9 契约测试的回滚用例。
- `taskFromPlanChange` 的物化规则（B4）：新 id、`status: TaskStatus.inbox`、`sourceMessageId: plan.sourceMessageId`、userId/deviceId 取仓储所在环境（DI 单例默认 `newUserId()`/`newDeviceId()`，与 M0 会话仓储一致）、`sortOrder: 0`；title/description/priority/dueAt 从 payload 读取（payload 见 §4.5，纯 JSON 类型）。

### 4.5 AIPlanChange JSON 编解码与 Task 物化（domain/entities/ai_plan.dart）

- 顶层函数 `Map<String, Object?> encodeChanges(List<AIPlanChange>)`：每条 `{type: 'createTask', taskId?, calendarEntryId?, payload}`；**payload 只允许 JSON 原生类型**：dueAt 存 ISO 字符串、priority 存字符串、其余 string/bool/num（B4）。
- 顶层函数 `List<AIPlanChange> decodeChanges(Object? json)`：非 List / 缺 type / 未知 type → 抛 `PlanValidationException`（数据完整性优先；与 Conversation metadata 的「宽容默认」不同——写注释说明理由）。
- 顶层函数 `Task taskFromPlanChange(AIPlanChange change, AIPlan plan, {required String userId, required String deviceId, required DateTime now})`：纯函数物化 createTask 变更（§4.2 规则）；change.type 非 createTask → 抛 `ConflictException`。

### 4.6 错误模型（core/errors/app_exception.dart）

- `PlanValidationException extends AppException`：AI 返回的 JSON 解析/校验失败、未知变更类型（中文 message 如「AI 返回的任务计划格式无效」）。
- `ConflictException extends AppException`：状态/数据冲突——confirm 非 awaitingConfirmation、applyChanges 中 update/delete 目标不存在、物化遇到非 createTask（中文 message 自定）。

### 5.2 TaskRepositoryImpl（Drift）+ MemoryTaskRepository

逐字实现 M0 接口（`watchTasks`/`getTasks`/`save`/`applyChanges`）：
- `save`：upsert（按 id 存在则 update 全字段 + `updatedAt=now`、`version+1`；不存在则 insert 补齐 Syncable 字段，规则同 M0 会话仓储）。
- `applyChanges(List<TaskChange>)`：`TaskInserted`→insert、`TaskUpdated`→update（含 version 递增）、`TaskDeleted`→软删除墓碑（`deletedAt=now, version+1`）；**先全量校验再提交**：update/delete 目标不存在 → 抛 `ConflictException` 且整体回滚/不提交。
- 查询下推（B3 口径，**status 集合过滤不做，在 UI 本地做**）：`watchTasks`/`getTasks` 只下推 `deletedAt IS NULL` + `TaskQuery` 的 `dueFrom/dueTo/text`（LIKE title|description）+ **单值** `status`（`projectId` 同时支持）；排序 `createdAt DESC`。内存版行为一致。
- **契约测试**（共享函数，参数化两实现）：CRUD、watch 过滤（单值 status/due 区间/LIKE）/软删、applyChanges 三事件、回滚（`[TaskInserted(合法), TaskDeleted('不存在')]` → 插入被回滚）、save 幂等 version。Drift 版用 `NativeDatabase.memory()`。

## 6. AI 计划协议（OpenAIClient.proposePlan）

### 6.1 系统提示（promptVersion = 'm1-plan-v1'，中文）

固定提示词，要求只输出一个 JSON 对象，禁止 markdown 代码块：

```text
你是「Alice」的个人执行助手。请把用户最近的需求拆解为任务清单，只返回 JSON：
{"intent":"一句话概括意图","tasks":[{"title":"任务标题","description":"可选说明","priority":"low|medium|high|urgent","dueAt":"可选，ISO8601 日期或 null"}]}
规则：1) 只输出 JSON，不要任何额外文字；2) 无法拆解时返回空 tasks，并用 intent 说明原因；
3) 不要编造用户未提出的截止时间。
```

调用细节：复用 `complete` 请求通路（model/baseUrl 取 `request.profile`），temperature 固定 0.2，`max_tokens` 取 profile；user message = `PlanRequest.request` 文本。

### 6.2 校验规则（非法一律抛 PlanValidationException，不落库）

1. 响应非合法 JSON / 非对象 → 抛。
2. `intent` 缺失或非字符串 → 抛。
3. `tasks` 缺失/非数组 → 抛；单个元素缺 `title`（非空字符串）→ 抛。
4. `priority` 缺失 → 默认 `medium`；非缺失值**先 `toLowerCase()` 归一**再对四枚举（low/medium/high/urgent）校验，仍不匹配 → 抛（S5）。
5. `dueAt` 缺失/null 合法；非空必须是可解析 ISO8601（含 `Z`/`+08:00`）→ **解析后统一 `toLocal()`** 再物化进 payload（S3）；无法解析 → 抛。
6. `AIPlanChange.type` 只接受 `createTask`（`updateTask/deleteTask/scheduleTask` 见到即抛——M1 能力外）。
7. **空 `tasks` 语义（S4）**：合法但视为「未能拆解」——不落库；`propose_task_plan.dart` 返回 `null`，UI 提示「未能拆解：<intent>」；**验收中的「非法不落任何业务数据」含此情况**。

### 6.3 结果

- 非空 tasks：返回 `AIPlan`：新 id、userId（仓储环境默认）、status=`awaitingConfirmation`、aiModel=响应 model、promptVersion='m1-plan-v1'、changes=createTask 列表（payload 按 §4.5 纯 JSON 规则：title、description?、priority（字符串）、dueAt?（ISO 字符串））。`intent` 仅用于空 tasks 的提示文案，不落库。
- 网络/非 2xx/解析错误沿用 `NetworkException`/`AIProviderException`；JSON 校验错误抛 `PlanValidationException`。
- 不打印 key/响应体。

### 8.2 任务页（features/tasks/tasks_screen.dart）

- 上半区（仅当有待确认计划时显示）：**待确认的 AI 拆解**卡片列表（`plan_preview_card.dart`）——标题 = **源用户消息**（截断，可追溯）、变更摘要（「将创建 N 个任务」+ 每行 title/priority/dueAt）、操作（✅ 确认 / ✕ 拒绝）、来源说明（模型 + 时间）。
- 下半区：任务列表。顶部过滤器 chips 三档（**B3：过滤在 UI 本地做**，数据源 `watchTasks(const TaskQuery())` 全量非删除任务）：
  - **今日**：`dueAt < 明日 00:00（本地）` 且 status ∉ {done, cancelled}，**含过期**（`dueAt < 今日 00:00` 红色「已过期」标注）；按 dueAt asc 排序；无 dueAt 的不显示。
  - **待办**：status ∈ {inbox, planned, doing}；createdAt desc。
  - **已完成**：status ∈ {done, cancelled}（cancelled 置灰）；createdAt desc。
- 任务条目：完成勾选（toggle done/inbox）、标题、优先级徽标（紧急红/高橙/默认灰）、截止时间 chip（今日/过期变色）、trailing 菜单：编辑 / 完成 / 取消。

### 8.3 聊天页「拆解为任务」

- ChatScreen AppBar actions 增加 `IconButton(Icons.checklist)`，tooltip「拆解为任务」。
- **可用态（S8）**：订阅 `watchMessages`，存在至少一条 role=user 的历史消息时可用，否则禁用（灰色）。
- 点击：取该会话最近一条 user 消息作 `PlanRequest`（含 `request.profile = settingsStore.currentProfile`）→ `propose_task_plan.dart`。结果 SnackBar：成功「已生成任务计划，请到任务页确认」；`AIPlan? == null` 时「未能拆解：<intent>」；`PlanValidationException` →「无法识别的任务计划」；其余异常显示其 message。请求进行中按钮转 loading、防重复点击。

### 8.4 AI 计划用例

- `propose_task_plan.dart`：入参 `PlanRequest` → `aiClient.proposePlan` → `plan.changes.isEmpty ? null : aiPlanRepository.save(plan)` → 返回 `AIPlan?`。
- `confirm_task_plan.dart`：入参 planId → `aiPlanRepository.confirm`；`reject_task_plan.dart` 同构 → `reject`。

### 8.5 设置页改动

- **回填（B2）**：`initState` 用 `_settingsStore.apiKey` 回填 key 输入框（打开页面即显示已存 key）；M0 的 `profile.apiKeyRef` 回填逻辑删除。
- 保存按钮：`await settingsStore.saveProfile(profile)` + `await settingsStore.saveApiKey(key)`（profile 不再携带 apiKeyRef）。**saveApiKey 抛 `StorageException` 时不阻断 saveProfile**：SnackBar「API Key 保存失败：安全存储不可用」，profile 保存成功照常提示「设置已保存」（S11）。
- 成功文案合并：非 key 失败时「设置已保存，API Key 已保存至安全存储」；key 失败时「设置已保存（API Key 未保存：安全存储不可用）」（实现自定，一句即可）。
